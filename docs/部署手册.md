## 1. 架构概览

```
EasyTier 客户端 (任意平台)
        │  wss://et.example.com/  (标准 WebSocket + EasyTier 二进制协议)
        ▼
Cloudflare Edge (Worker 入口 src/index.js)
        │  按 URL/Header/Query 选择房间 → 转发到 Durable Object
        ▼
RelayRoom Durable Object (src/room.js)
        │  握手鉴权 → 路由同步(OSPF) → 包转发
        ▼
同一网络的其他客户端（经中继兜底；P2P 打洞成功后直连，不再经过本节点）
```

**纯 P2P 模式**：节点在路由协议中宣告 `avoid_relay_data`（OSPF 大代价边），
客户端之间优先直连；只有 P2P 打洞失败的流量才走中继兜底（可通过 `RELAY_DATA=0` 完全关闭数据面）。

## 2. 前置条件

| 项目 | 要求 |
|---|---|
| Cloudflare 账号 | 免费计划即可（SQLite 后端 Durable Objects 已对免费计划开放） |
| Node.js | ≥ 18（推荐 20+） |
| Wrangler | v4.x（`npm i -g wrangler` 或使用项目内 npx） |
| 自定义域名 | 可选；域名需托管在 Cloudflare（用 Workers 默认 `*.workers.dev` 域名则不需要） |

## 3. 快速部署（5 分钟）

```bash
# 1. 进入项目目录
cd easytier-cf-relay

# 2. 安装依赖
npm install

# 3. 登录 Cloudflare（浏览器授权）
npx wrangler login

# 4. 部署
npx wrangler deploy

# 5. 验证（把 <name> 替换为 wrangler 输出的 Worker 名）
curl https://easytier-cf-relay.<你的子域>.workers.dev/health
# 期望: {"ok":true}
```

客户端即可用 `wss://easytier-cf-relay.<你的子域>.workers.dev/` 作为节点地址。

> **可选：启用 KV 审计（记录 + 黑名单）**——创建 KV namespace 并在 wrangler.toml
> 启用 `AUDIT_KV` 绑定（见 5.6 节）。不配置时功能自动降级为仅 DO storage 存储，
> 管理页功能不受影响。

> **本地验证**（可选，无需账号）：`npx wrangler dev --port 8787` 后用官方客户端
> `easytier-core -p ws://127.0.0.1:8787/` 连接验证。
> 本地 `wrangler dev` 会自动读取 `.dev.vars`（已 gitignore，不随 deploy 上传）。

## 4. 绑定自定义域名

### 方式 A：Custom Domain（推荐）

域名已托管在 Cloudflare 时，在 `wrangler.toml` 追加：

```toml
routes = [
  { pattern = "et.example.com", custom_domain = true }
]
```

重新 `npx wrangler deploy`。Cloudflare 会自动：
- 创建 DNS 记录
- 签发并轮换 TLS 证书（免费）

### 方式 B：Route + 手动 DNS

```toml
routes = [
  { pattern = "et.example.com/*", zone_name = "example.com" }
]
```

并在 Cloudflare DNS 面板为 `et.example.com` 添加任意 A/AAAA 记录（如 `192.0.2.1`，流量走 Worker 不回源）。

### 客户端 URL 格式

```
wss://et.example.com/
```

路径任意（`/`、`/ws`、`/easytier` 均可），与官方服务端行为一致——因为部分客户端
（含官方 GUI）会把用户配置的路径原样带到 WebSocket 升级请求里。

## 5. 配置参考

所有配置通过 `wrangler.toml` 的 `[vars]`（或 `wrangler secret`）设置，改完重新 deploy 生效。

### 5.1 基础配置

| 变量 | 默认值 | 说明 |
|---|---|---|
| `SERVER_PEER_ID` | `10000001` | 服务端虚拟 Peer ID。避免与客户端随机 ID 冲突（客户端 ID 为大随机数） |
| `SERVER_NETWORK_NAME` | `public_server` | 握手响应中宣告的网络名。与客户端网络名不同 ⇒ 官方客户端按"外部网络中继"处理（行为与官方公共服务器一致） |
| `SERVER_HOSTNAME` | `easytier-cf-relay` | 节点主机名（路由表中显示） |
| `SERVER_VERSION_STR` | `easytier-cf-relay/1.2.0` | 节点版本串（`easytier-cli peer` 可见） |

### 5.2 P2P 与转发行为

| 变量 | 默认值 | 说明 |
|---|---|---|
| `AVOID_RELAY_DATA` | `1` | 纯 P2P 模式：在 feature_flag 中宣告 `avoid_relay_data`，OSPF 给本节点边赋大代价，客户端优先直连 |
| `RELAY_DATA` | `1` | P2P 失败时的兜底：`1` 转发 Data/KCP 数据包；`0` 丢弃（严格纯 P2P，只保留控制面） |

### 5.3 容量与超时

| 变量 | 默认值 | 说明 |
|---|---|---|
| `MAX_PEERS_PER_ROOM` | `64` | 单房间最大 peer 数（含所有网络分组） |
| `MAX_MESSAGE_BYTES` | `131072` | 单条 WS 消息上限（128 KiB，远大于 EasyTier MTU 1380 与路由同步包） |
| `HANDSHAKE_TIMEOUT_MS` | `15000` | 连接后未完成握手的清理超时（防幽灵连接第一道防线） |
| `PEER_IDLE_TIMEOUT_MS` | `75000` | 空闲超时。**必须 > 客户端 ping 最大间隔 32s**（防幽灵节点第二道防线） |
| `SERVER_PING_IDLE_MS` | `40000` | 服务端主动 ping 阈值，探测半开连接（第三道防线） |
| `ROUTE_INFO_UNREACHABLE_MS` | `90000` | 路由条目老化（防线五）：条目未刷新且节点不可达（无连接且 PeerCenter 无可达路径）超过该时长 → 删除。对齐官方 `clear_expired_peer` 语义 |
| `ROUTE_INFO_TTL_MS` | `3660000` | 路由条目老化（防线五）：条目未刷新超过该时长 → 无条件删除（61 分钟） |
| `GROUP_AUTO_DELETE_MS` | `60000` | 空分组自动删除宽限（防线六）：分组内在线节点归零后持续该时长仍为空 → 整组删除（含路由条目与摘要注册）；`0` = 关闭 |
| `SWEEP_INTERVAL_MS` | `15000` | Durable Object alarm 清扫周期（老化与空分组删除也在此周期内执行） |

### 5.4 安全

| 变量 | 默认值 | 说明 |
|---|---|---|
| `STRICT_DIGEST` | `1` | `1`：同一网络名出现不同 network_secret 摘要 ⇒ 拒绝（防网络名抢占/嗅探）；`0`：隔离为不同分组 |
| `NETWORK_SECRETS` | （空） | 可选 JSON 映射 `{"网络名":"密钥"}`。配置后服务端用 **SipHash-1-3**（与官方同一算法）校验客户端摘要，密钥不匹配直接拒绝 |

```toml
# 示例：校验两个网络的密钥
[vars]
NETWORK_SECRETS = "{\"myteam\":\"s3cret!\",\"family\":\"home123\"}"
```

> 不配置 `NETWORK_SECRETS` 时，任何持有正确 `(网络名, 密钥)` 组合的客户端都可接入
> ——与官方公共服务器 `public.easytier.cn` 的行为一致（不同密钥的网络天然隔离，互不可见）。

### 5.5 多房间分片（可选）

默认所有连接进同一个 DO 房间 `"global"`（同房间内按网络名+摘要自动分组隔离）。
需要物理隔离（例如不同租户）时：

```toml
[vars]
ROOM_HEADER = "X-Room"       # 按请求头分片
# 或
ROOM_QUERY = "room"          # 按 URL 查询参数分片，如 wss://et.example.com/?room=t1
```

### 5.6 KV 审计（记录 + 黑名单）

六类信息（网络分组 / 节点在线 / 路由信息 / 全局互联 / 连接列表 / 摘要注册表）的
连接与事件记录进 Workers KV，**每类只占一条 KV 键**（记录 7 条 + 黑名单 4 条，共 11 条）；
管理端另有黑名单（分四类：节点 PeerId / 网络分组 / 摘要注册 / 客户端 IP）。

**启用步骤**（可选；不配置 KV 绑定时功能优雅降级——记录与黑名单仅存
Durable Object storage，管理页功能不变）：

```bash
# 1. 创建 KV namespace（免费计划自带）
npx wrangler kv namespace create AUDIT_KV
# 输出 id 后填入 wrangler.toml：

[[kv_namespaces]]
binding = "AUDIT_KV"
id = "<上面输出的 id>"

# 2. 重新部署
npx wrangler deploy
```

| 变量 | 默认值 | 说明 |
|---|---|---|
| `RECORD_FLUSH_MS` | `600000` | KV 镜像最小间隔（毫秒）。事件先写内存 + DO storage，按此间隔节流写 KV（控制免费额度写入量） |
| `RECORD_DEFAULT_LIMIT` | `100` | 各类记录默认条数上限（管理页「记录设置」可单独调整） |
| `BLACKLIST_LIMIT` | `1000` | 各类黑名单条数上限（**硬设置**） |
| `ADMIN_AUDIT` | `1` | **硬设置**：管理端审计开关。记录管理员登录（IP/时间）、操作、查看信息；管理页不可关闭，admin 类记录不可删除 |
| `ADMIN_AUDIT_LIMIT` | `200` | 管理端审计记录上限（**硬设置**） |

KV 键布局与写入策略详见技术文档 §9。免费额度核算：
KV 免费计划 1000 写/天——默认 10 分钟节流下每键理论最大 144 写/天，
实际仅在有新事件的周期产生写入（典型小网络全类合计每天数十次），远低于限额；
读取仅在冷启动且 DO storage 为空时发生（每键一次）。

**黑名单行为**：管理页执行「踢出节点 / 删除分组 / 删除摘要注册 / 断开连接」时，
操作对象（PeerId / 网络名 / IP）自动进入对应类别黑名单并被拦截后续接入；
黑名单页可手工添加、移除（解除封锁）或清空。断开连接会拉黑该客户端 IP——
若多个节点共用同一出口 IP，请谨慎使用（可先移除该 IP 再让其重连）。

### 5.8 监控与管理端

**生产环境默认全部禁用**（不配置即 404，零攻击面）。启用时务必使用
**随机长路径 + 强 token 双重防线**：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `METRICS_PATH` | （空） | 统计端点自定义安全路径。不配置则 `/metrics` 完全禁用 |
| `METRICS_TOKEN` | （空） | 统计端点 token（`Authorization: Bearer <t>` 或 `?token=<t>`）。**与 `METRICS_PATH` 同时配置才启用（fail-closed）** |
| `ADMIN_PATH` | （空） | Web 管理端路径。**与 `ADMIN_TOKEN` 同时配置才启用**（页面壳公开、数据 API 鉴权） |
| `ADMIN_TOKEN` | （空） | 管理端 token（状态查看 / 踢出节点 / 删除分组） |

```toml
[vars]
METRICS_PATH = "/m-a1b2c3d4"              # 用 openssl rand -hex 8 生成
METRICS_TOKEN = "长随机字符串"
ADMIN_PATH = "/console-e5f6a7"
ADMIN_TOKEN = "另一个长随机字符串"
```

要点：

- 鉴权失败统一返回 **404**（不暴露端点存在性）；token 比较为常数时间（防时序侧信道）；
- 管理端页面壳本身无数据（可公开访问），所有数据 API 均需 token；
- **token 属于敏感信息**：生产建议用 `npx wrangler secret put METRICS_TOKEN` 注入而非写进 toml；
- 管理页自动刷新间隔 10s，长开页面的请求量约 8.6k/天，对免费额度（100k/天）占用很小，
  不需要时可关闭自动刷新。

## 7. 成本与额度

**免费计划即可运行本服务**（SQLite 后端 Durable Objects 已对免费计划开放）。关键额度：

| 维度 | 免费计划 | 说明 |
|---|---|---|
| 请求 | 100,000 / 天 | 含 WS 连接建立、**入站 WS 消息（20:1 折算）**、alarm 唤醒 |
| Duration | 13,000 GB-s / 天 | **Hibernation 状态不计费** —— 本实现全用 Hibernation API，空闲时成本趋近零 |
| 存储 | 5 GB / 账户 | 本服务仅存路由元数据（KB 级） |
| KV 写 | 1,000 / 天 | 启用 KV 审计后：事件按 `RECORD_FLUSH_MS`（默认 10 分钟）节流镜像，每键理论最大 144 写/天 |
| KV 读 | 100,000 / 天 | 仅冷启动且 DO storage 为空时读取（每键一次） |
| 单 DO 吞吐 | ~1,000 req/s（软限制） | 单房间 64 peer 远达不到 |

成本估算（10 个客户端、每客户端 8s 一次心跳的典型小网络）：
- 计费请求 ≈ 10 × (86400/8) / 20 ≈ **5,400 请求/天**，远低于 10 万限额；
- duration：连接空闲即休眠，**活跃处理时间每天累计不足 1 GB-s**；
- KV 审计：每天几十次连接波动 × 涉及的 2~3 个键 ÷ 10 分钟节流合并 ≈ **数十写/天**，
  远低于 1000/天限额（记录上限 100 条/类，存储占用 KB 级）；
- 结论：**免费额度内稳定运行**。超出时可升级 Workers Paid（$5/月起，含 100 万请求/月 + 40 万 GB-s/月）。

计费细节参见 Cloudflare 官方文档：
- [Durable Objects 定价](https://developers.cloudflare.com/durable-objects/platform/pricing/)
- [Durable Objects 限制](https://developers.cloudflare.com/durable-objects/platform/limits/)

## 8. 运维：日志、监控、升级

### 8.1 健康检查与指标

```bash
# 健康检查：零指纹（P0 整改后仅返回 {"ok":true}）
curl https://et.example.com/health
# {"ok":true}

# 统计：自定义安全路径 + token（未配置 METRICS_PATH/METRICS_TOKEN 时 404）
curl -H "Authorization: Bearer <METRICS_TOKEN>" https://et.example.com<m-metrics-path>
# {
#   "ok": true, "totalPeers": 2, "groupCount": 1,
#   "groups": { "myteam:<digest>": { "peers": [...], "knownInfos": 3 } },
#   "counters": { "msgsIn": 103, "msgsOut": 103, "forwards": 58, "errors": 0, ... }
# }
```

字段速查：`forwards` = 数据包中继次数；`errors` = 协议错误数（应恒为 0）；
`forgeries` = 源伪造拦截数（F-06 防线命中）；`groups` 按网络名分组列出在线 peer ID。

### 8.2 Web 管理端

配置 `ADMIN_PATH` + `ADMIN_TOKEN` 后，浏览器打开 `https://et.example.com<ADMIN_PATH>`
进入控制台（输入 token 即可，浏览器本地保存）。

**界面结构**（侧边栏列表式导航，按功能块分区）：

- **总览**（对照 `easytier-cli stats` / `node`）：运行时长（自房间创建起累计，含休眠）、分组数、
  在线节点、收发包/字节/转发/错误计数，以及审计概览（记录/黑名单各分类计数与 KV 状态）；
- **节点在线**（对照 `easytier-cli peer`）：各分组在线节点、连接时间、最近活动，可**踢出节点**；
- **路由信息**（对照 `easytier-cli route`）：RoutePeerInfo 路由表，含 direct/transit 来源标记
  与幽灵条目标记（transit 来源 + 无连接），可**删除条目**；
- **全局互联**（对照 `easytier-cli peer-center`）：PeerCenter 互联表，可**删除条目**；
- **连接列表**：全部 socket（含未握手），含 socket ID 与客户端 IP，可**断开连接**；
- **网络分组**（对照 `easytier-cli foreign-network`）：按网络名+摘要隔离的分组，可**删除分组**；
- **摘要注册表**：网络名 → 摘要注册（STRICT_DIGEST 判定依据），可**删除注册**；
- **记录查询**：七类记录（六类数据 + 管理端审计）分页浏览，单条/批量删除与清空
  （admin 类为硬审计，只读）；
- **记录设置**：六类数据记录各自的开/关与条数上限（管理端审计与黑名单上限为硬设置，只读展示）；
- **黑名单**：四类黑名单（节点 PeerId / 网络分组 / 摘要注册 / 客户端 IP）分页浏览，
  手工添加、单个/批量移除（解除封锁）与清空。

**性能设计**（节点多时页面不爆炸）：

- **服务端分页**：所有列表 `?tab=&offset=&limit=` 分页拉取，每页默认 50 条（可选 20/50/100/200，上限 200）；
- **独立滚动**：列表区固定最大高度、内部滚动，表头 sticky；
- **按块统计**：每个功能块头部显示自身统计（总数/直连/中转/幽灵/空分组等），
  侧边栏实时显示各块计数；
- **批量操作**：每个功能块支持勾选（单选/全选本页）+ 批量按钮
  （删除分组 / 踢出节点 / 删除路由 / 删除互联 / 断开连接 / 删除摘要注册）；
- **自动刷新仅拉取当前 tab**（10s，可关闭），开销可控。

**删除分组**：断开组内全部连接、清除路由/会话数据、解除摘要注册
（被恶意摘要抢占时可用此操作解锁）。注意：删除分组 / 踢出节点 / 删除摘要注册 /
断开连接会把操作对象（网络名 / PeerId / IP）自动加入对应类别的**黑名单**并拦截
后续接入，需要放行时到「黑名单」页移除即可（见 5.6 节）。

官方 CLI 中依赖 UDP/TUN/系统服务的命令（`connector`、`vpn-portal`、`stun`、`acl` 等）
在 Workers 运行时不可用，控制台底部有完整对照表。

也可直接调 API（鉴权方式同上）：

```bash
# 查看状态（tab: overview/groups/peers/routes/peercenter/sockets/digests；分页 offset/limit）
curl -H "Authorization: Bearer <ADMIN_TOKEN>" \
  "https://et.example.com<ADMIN_PATH>/api/state?tab=routes&offset=0&limit=50"

# 踢出节点（单个或批量）
curl -X POST -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "content-type: application/json" \
  -d '{"peers":[{"groupKey":"myteam:<digest>","peerId":12345678}]}' \
  https://et.example.com<ADMIN_PATH>/api/peer/kick

# 删除分组（支持 groupKeys 数组 / networkName / all）
curl -X POST -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "content-type: application/json" \
  -d '{"networkName":"myteam"}' \
  https://et.example.com<ADMIN_PATH>/api/group/delete

# 删除路由条目（批量；在线节点的 direct 条目会被跳过）
curl -X POST -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "content-type: application/json" \
  -d '{"groupKey":"myteam:<digest>","peerIds":[12345678,12345679]}' \
  https://et.example.com<ADMIN_PATH>/api/route/delete

# 删除互联表条目（批量）
curl -X POST -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "content-type: application/json" \
  -d '{"groupKey":"myteam:<digest>","peerIds":[12345678]}' \
  https://et.example.com<ADMIN_PATH>/api/peercenter/delete

# 断开指定连接（批量，按 socketId）
curl -X POST -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "content-type: application/json" \
  -d '{"socketIds":[3,5]}' \
  https://et.example.com<ADMIN_PATH>/api/socket/close

# 删除摘要注册（批量；连带清除使用该摘要的分组并断开其连接）
curl -X POST -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "content-type: application/json" \
  -d '{"networkNames":["myteam"]}' \
  https://et.example.com<ADMIN_PATH>/api/digest/delete

# ---- KV 审计（记录 + 黑名单）----

# 查询记录（type: groups/peers/routes/peercenter/sockets/digests/admin；分页）
curl -H "Authorization: Bearer <ADMIN_TOKEN>" \
  "https://et.example.com<ADMIN_PATH>/api/records?type=peers&offset=0&limit=50"

# 删除记录（ids 为记录 id 数组或 "all"；admin 类返回错误——硬审计不可删）
curl -X POST -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "content-type: application/json" \
  -d '{"type":"peers","ids":"all"}' \
  https://et.example.com<ADMIN_PATH>/api/records/delete

# 读取 / 修改记录配置（每类开关 + 上限；admin 类不在可改范围）
curl -H "Authorization: Bearer <ADMIN_TOKEN>" \
  "https://et.example.com<ADMIN_PATH>/api/record/config"
curl -X POST -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "content-type: application/json" \
  -d '{"types":{"peers":{"on":true,"limit":200}}}' \
  https://et.example.com<ADMIN_PATH>/api/record/config

# 查询黑名单（cat: peer/group/digest/socket）
curl -H "Authorization: Bearer <ADMIN_TOKEN>" \
  "https://et.example.com<ADMIN_PATH>/api/blacklist?cat=peer&offset=0&limit=50"

# 手工拉黑（cat + value；peer 为数字 PeerId，group/digest 为网络名，socket 为 IP）
curl -X POST -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "content-type: application/json" \
  -d '{"cat":"peer","value":12345678,"reason":"abuse"}' \
  https://et.example.com<ADMIN_PATH>/api/blacklist/add

# 移除黑名单（解除封锁；ids 为条目 id 数组或 "all"）
curl -X POST -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "content-type: application/json" \
  -d '{"cat":"peer","ids":"all"}' \
  https://et.example.com<ADMIN_PATH>/api/blacklist/delete
```

### 8.5 Durable Object 迁移注意

本工程 `wrangler.toml` 使用：

```toml
[[migrations]]
tag = "v1"
new_sqlite_classes = ["RelayRoom"]
```

- **全新部署**：保持原样即可。
- **接手已有 `new_classes`（KV 后端）的旧部署**：不要删掉旧 migration 条目，改为追加：

```toml
[[migrations]]
tag = "v1"
new_classes = ["RelayRoom"]     # 旧条目原样保留

[[migrations]]
tag = "v2"
new_sqlite_classes = ["RelayRoom"]  # 追加：切换到 SQLite 后端
```

## 9. 故障排查 FAQ

**Q1：客户端一直 `connect timeout after 20s`？**
1. `curl https://你的域名/health` 确认 Worker 存活；
2. 检查 URL scheme 是 `wss://`（而非 `ws://`，Workers 强制 TLS）；
3. `npx wrangler tail` 看握手是否到达。到达但被拒（digest mismatch）说明密钥不对。

**Q2：客户端握手成功但 `easytier-cli peer` 看不到服务端节点？**
通常是旧版本第三方实现的问题；本项目已实测 2.6.4 正常显示（hostname=cf-relay）。
若遇到，开启 `LOG_LEVEL=debug` 检查 `rpc req ... service=OspfRouteRpc` 日志行，
存在但无响应时请提 issue 附日志。

**Q3：节点显示在线，但互相 ping 不通？**
- 确认两端 `--network-name` 与 `--network-secret` 完全一致（STRICT_DIGEST=1 时不同摘要会被拒绝，日志有 `digest mismatch`）；
- `RELAY_DATA=0` 时中继不转发数据面，必须依赖 P2P 直连（打洞失败的组合无法通信），需要兜底请设 `RELAY_DATA=1`。

**Q4：本地 `wrangler dev` 报 `Address already in use`？**
端口被占用：`npx wrangler dev --port 8788` 换端口，或杀掉旧进程。

**Q5：`wrangler deploy` 报 DO 类已存在 / migration 冲突？**
见 8.4 迁移章节。切勿删除 `wrangler.toml` 中已有的 `[[migrations]]` 条目。

**Q6：两个客户端都能连上，但互相看不到对方（只看得到 cf-relay）？**
检查是否误配置了 `ROOM_HEADER`/`ROOM_QUERY`——两个客户端进了不同 DO 房间。
同房间要求相同的 URL/Header。

**Q7：想统计流量？**
配置 `METRICS_PATH` + `METRICS_TOKEN` 后访问统计端点，
`counters.bytesIn/bytesOut/forwards` 即为控制面+数据面的转发统计；或用 Web 管理端总览页。

**Q8：同名网络被恶意抢占（digest mismatch）怎么办？**
已配置 `NETWORK_SECRETS` 的网络不受影响（服务端以正确密钥摘要为准，注册表自愈）。
未配置的网络被抢占时，用管理端**删除该分组**即可解除注册，随后正常客户端可重新接入。

**Q9：踢出/删除的节点或网络重连不上？**
这是黑名单在生效：踢出节点 / 删除分组 / 删除摘要注册 / 断开连接会把操作对象
（PeerId / 网络名 / IP）加入对应类别黑名单并拦截后续接入。
到管理端「黑名单」页移除对应条目（解除封锁）即可重新接入。
注意：断开连接拉黑的是客户端 IP——若多个节点共用同一出口 IP，会一并被拦，
需要时先移除该 IP 条目。

**Q10：管理端记录为什么删不掉 / 关不掉？**
管理端审计（登录 IP/时间、操作、查看）是**硬设置**（wrangler.toml `ADMIN_AUDIT`），
管理页不可关闭、admin 类记录不可删除（防审计自擦除）。
六类数据记录则可在「记录设置」页单独开关并设置上限。
