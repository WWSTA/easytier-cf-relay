## \[1.2.0\] - 2026-08-31

在 1.0.0 协议完备的基础上补齐「可观测 + 可管控」：新增 KV 审计记录与管理端黑名单，
管理控制台新增三个页面（记录查询 / 记录设置 / 黑名单）。协议层无变更，与 1.0.0 完全兼容。

### 新增 — KV 审计记录

* 六类网络事件记录进 Workers KV：网络分组 / 节点在线 / 路由信息 / 全局互联 / 连接列表 /
  摘要注册（**每类只占一条 KV 键**，定长环形缓冲；连同管理端审计与黑名单全生命周期共 11 条键）
* 事件明细：分组 create / delete（含原因）、节点 join / leave / replace / reject（含 IP）、
  路由 add / remove（direct / transit 与顶替记录）、互联 add / remove（含 TTL 过期）、
  连接 open / close / error（含 socketId、IP）、摘要 register / delete
* 管理端硬审计：管理员登录（IP / 时间）、查看（5 分钟折叠计数）、操作明细；
  `ADMIN_AUDIT` 为硬开关，管理页不可关闭，admin 类记录不可删除（防审计自擦除）
* 三级写入路径控成本：事件先入内存数组 → alarm 周期落 DO storage（防休眠丢失）→
  KV 镜像仅写脏键并按 `RECORD_FLUSH_MS`（默认 10 分钟）节流；管理操作完成后强制刷 KV
  （黑名单立即生效）。免费额度 1000 写/天下默认每键最多 144 写/天，典型小网络每天合计数十次
* 未配置 `AUDIT_KV` 绑定时优雅降级为仅 DO storage 存储，管理页功能不受影响

### 新增 — 管理端黑名单

* 四类黑名单各占一条 KV 键：节点 PeerId / 网络分组（网络名）/ 摘要注册 / 客户端 IP
* 管理操作自动拉黑：踢出节点 → peer；删除分组 → group（网络名）；删除摘要注册 → digest；
  断开连接 → socket（已知客户端 IP）
* 双拦截点：WebSocket 升级时按客户端 IP 403 拒绝；握手（摘要校验前）按 peer / group / digest
  关闭连接（4013 blacklisted），拒绝事件记入节点记录
* 黑名单页支持手工添加（含备注原因）、单个与批量移除（解除封锁）、整类清空；
  上限 `BLACKLIST_LIMIT`（默认 1000）为硬设置

### 新增 — Web 管理端（三个新页面）

* 记录查询：按类型筛选 + 分页浏览六类记录与管理端审计，支持单个与批量删除（admin 类不可删）
* 记录设置：六类记录各自的开 / 关与条数上限（软设置，运行时生效，收紧上限时立即裁剪旧记录）
* 黑名单：四类黑名单的查询 / 添加 / 移除 / 清空，含各类条数统计
* 侧边栏新增「记录查询 / 记录设置 / 黑名单」功能块与统计徽标，总览页汇总审计统计

### 新增 — 配置项（wrangler.toml）

* `AUDIT_KV` KV namespace 绑定（可选）
* `RECORD_FLUSH_MS`（KV 镜像节流间隔，默认 600000）
* `RECORD_DEFAULT_LIMIT`（各类记录默认上限，默认 100）
* `BLACKLIST_LIMIT`（各黑名单上限，默认 1000）
* `ADMIN_AUDIT` / `ADMIN_AUDIT_LIMIT`（管理端审计硬开关与上限，默认开 / 200）

### 修复

* 运行时长在 DO 休眠或重启后重新计时的问题：首次启动时间持久化到 DO storage，
  现按房间首次创建起累计（含休眠时间），管理页附说明提示
* 管理端命名与统计口径统一：连接（sockets）与管理端审计纳入总览统计，
  侧边栏徽标与总览汇总一致

## \[1.0.0\] - 2026-08-26

首个公开发布版本。协议行为以官方 easytier-core **v2.6.4** 源码为基准逐项对齐，
并使用官方客户端实测验证：握手、路由同步、双节点互见、数据中继、长稳运行全部通过。

### 新增 — 协议层（对标官方 easytier-core 2.6.4）

* ZCPacket / PeerManagerHeader（16 字节小端头）解析与构造

* WebSocket 隧道：接受任意路径的升级请求（与官方服务端行为一致）

* 握手：magic / version / features 镜像 / 网络摘要校验
  （SipHash-1-3，与官方同算法同密钥派生）

* Ping/Pong 心跳：payload 原样回显（支持客户端自增 seq），liveness-echo flags 镜像

* RPC 分发：RpcPacket / RpcRequest / RpcResponse，int64 transaction\_id 全精度

* OspfRouteRpc.SyncRouteInfo：请求处理 + 响应 + 主动推送（全量 / 增量）

* 路由增量同步：version / peer\_route\_id / session 语义（peer\_route\_id 变化即无条件替换）

* RoutePeerInfo 未知字段逐字节保留（wire 层重组，对标官方 raw\_peer\_infos 机制）

* PeerCenterRpc.ReportPeers / GetGlobalPeerMap：官方 replace 语义 + digest 缓存

* 包转发：forward\_counter 每跳 +1、>7 丢弃、转发时清除 LATENCY\_FIRST

* 同 peerId 重连顶替：旧连接关闭 + 路由更新广播

* 加密包（ENCRYPTED flag）透传不受影响

* 网络分组隔离：网络名 + 摘要 → 独立分组，互不可见

### 新增 — 平台层（Cloudflare Workers）

* Worker 入口：`/health` 零指纹；`/metrics` 与 Web 管理端为自定义安全路径 + token
  双门禁（fail-closed，不配置即 404，零攻击面）

* RelayRoom Durable Object：全 WebSocket Hibernation API，全程零 setInterval/setTimeout 常驻

* Alarm 驱动周期清扫（DO 可休眠，duration 成本趋零，免费额度内稳定运行）

* attachment 元数据：休眠唤醒后恢复 peerId / groupKey / lastSeen

* 路由状态持久化：脏标记 + 节流落盘，损坏数据静默丢弃

* 多房间分片（Header / Query 可配置）

### 新增 — Web 管理端

* 侧边栏列表式导航：总览 / 网络分组 / 节点在线 / 路由信息 / 全局互联 / 连接列表 / 摘要注册表

* 服务端分页 + 各列表独立滚动：节点数量大时打开管理页不卡不爆

* 各功能块自带统计（侧边栏徽标 + 总览页汇总）

* 全功能块批量操作（单个与批量均支持）：踢出节点 / 删除分组 / 删除路由条目 /
  删除互联条目 / 断开连接 / 删除摘要注册

* 路由信息与摘要注册表支持单独删除

* 官方 easytier-cli 命令对照表

* 数据 API 全部经 token 鉴权（页面壳公开、数据不公开）

### 新增 — 稳定性与自动清理

* 幽灵节点六重防线（详见技术文档 §6）：

  * 连接级：握手超时（15s）/ 空闲超时（75s）/ 服务端主动探活（40s）

  * 路由级：direct/transit 来源标记（transit 永不覆盖 direct）+ reporter 追踪 /
    路由老化（对齐官方 `clear_expired_peer` 两层语义：不可达 90s / TTL 3660s）/
    空分组自动删除（宽限 60s）

* 空分组自动删除：分组内在线节点归零并持续超过宽限期 → 整组删除（含路由条目与摘要注册）

* 摘要注册表自愈：孤儿摘要注册随分组删除一并解除，不留脏数据

### 新增 — 安全加固

* STRICT\_DIGEST：同一网络名出现不同摘要时拒绝（防网络名抢占）

* NETWORK\_SECRETS：服务端侧网络密钥校验（SipHash-1-3 摘要比对）

* MAX\_MESSAGE\_BYTES / MAX\_PEERS\_PER\_ROOM 资源限制

* 转发前校验 from\_peer\_id 与连接注册身份一致（伪造源丢弃并计数）

* 路由 transit 条目不覆盖 direct 条目（防路由投毒 / 防幽灵复活）

* PeerCenter 上报以连接注册身份为准（防身份冒用）

### 修复（开发过程中定位并解决）

* **幽灵节点（重大）**：客户端多 PeerId 竞争后，被放弃的 PeerId 作为 transit 条目
  被其他节点转述上报，导致路由表出现"无在线连接的幽灵条目"（节点实际只有一个连接）。
  通过 reporter 追踪（上报者断开即清除其上报的无主 transit 条目）+ direct 覆盖规则 +
  路由老化三层机制根除，同类残留此后自动清理。

* 管理端"官方 easytier-cli 命令对照"表格右侧溢出：容器改为允许横向滚动。

* `wrangler deploy` 多环境警告：deploy / dry-run 脚本显式指定 `--env=""`，
  明确使用顶层环境，避免误部署到错误环境。

### 已知限制

* 不支持 secure mode（Noise，v2.6.0+ 可选加密握手）——客户端使用默认模式即可

* 不执行 P2P 打洞（Workers 无 UDP 出口），仅提供 rendezvous；双端严格 NAT 时走中继

* 不做 KCP/QUIC 协议转换（相关包按 to\_peer\_id 原样转发，无功能影响）

* 单房间为 DO 单线程串行（软限制 \~1000 req/s）；更大规模使用房间分片

完整列表见技术文档 §11。
